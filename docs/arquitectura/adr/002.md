# [ADR-0002] Adopción de Kong API Gateway como Capa de Intermediario

* **Estado:** Aceptado
* **Decisores:** Equipo de Desarrollo de Software (Backend Java/Angular)
* **Stakeholders:** Equipo de Arquitectura, DevOps y Negocio
* **Fecha:** 2026-11-10

---

## 1. Contexto y Declaración del Problema

Para implementar patrones de modernización como el *Strangler Fig* y gestionar el tráfico entre el sistema legado y los nuevos microservicios, se requiere una capa de fachada (API Gateway o reverse proxy) eficiente y robusta que intercepte y enrute las peticiones de manera centralizada sin degradar el rendimiento global de la plataforma.

---

## 2. Opciones Consideradas

* **Opción 1:** Gateway basado en Java / Spring Cloud Gateway.
* **Opción 2:** Proxy basado en Node.js.
* **Opción 3:** Kong API Gateway (basado en NGINX / OpenResty).

---

## 3. Decisión Tomada

Decidimos seleccionar la **[Opción 3: Kong API Gateway]** porque ofrece un rendimiento superior con un consumo mínimo de recursos gracias a su arquitectura sobre NGINX.

### Razones Principales de la Elección
* Razón 1: Aprovecha el modelo asíncrono y no bloqueante impulsado por eventos de NGINX.
* Razón 2: Introduce una latencia prácticamente imperceptible en el enrutamiento de peticiones.
* Razón 3: Presenta un consumo de memoria y CPU significativamente menor en comparación con entornos más pesados.

---

## 4. Análisis Comparativo de Opciones (Pros y Contras)

### Opción 1: Spring Cloud Gateway (Java)
* **Ventajas:**
  * Alineado con ecosistemas basados puramente en Java.
* **Desventajas:**
  * Mayor consumo de memoria y CPU debido al entorno de ejecución más pesado.

### Opción 2: Proxies basados en Node.js
* **Ventajas:**
  * Flexibilidad en el ecosistema JavaScript.
* **Desventajas:**
  * Mayor consumo de recursos y menor optimización nativa a nivel de infraestructura para el enrutamiento perimetral masivo comparado con NGINX.

### Opción 3: Kong API Gateway
* **Ventajas:**
  * Rendimiento extremo con latencia en milisegundos.
  * Consumo de recursos sumamente contenido.
  * Ecosistema maduro de plugins de seguridad y control de tráfico.
* **Desventajas:**
  * Curva de aprendizaje inicial en la configuración de sus plugins y modelos de despliegue.

---

## 5. Consecuencias e Impacto

### Positivas (Beneficios)
* Optimización del rendimiento y reducción de cuellos de botella en la capa de entrada.
* Alta eficiencia en el uso de recursos de infraestructura (CPU y memoria).
