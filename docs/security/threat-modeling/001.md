# Modelo de amenazas: `/api/v1/products/{1}`

## 1. Alcance y supuestos del endpoint

* **Ruta:** `/api/v1/products/{id}`
* **Métodos probables:**
  * `GET`: Consultar detalles de un producto.
  * `PUT` / `PATCH`: Actualizar información, precio o stock de un producto.
  * `DELETE`: Eliminar un producto.
---

## 2. Análisis de amenazas (Metodología STRIDE)

| Categoría STRIDE | Amenaza específica en `/api/v1/products/{1}` | Impacto | Mitigaciones recomendadas |
| :--- | :--- | :--- | :--- |
| **Suplantación de identidad** | Un atacante usa un token robado, expirado o débilmente validado para llamar a `PUT`, `PATCH` o `DELETE` haciéndose pasar por un administrador o vendedor. | **Alto** | Exigir autenticación robusta (JWT/OAuth2 con firma verificada), validar expiración (`exp`), audiencia (`aud`) y emisor (`iss`), y usar HTTPS obligatorio. |
| **Manipulación de datos** | Modificación no autorizada de precios, descuentos, descripciones o stock mediante `PUT`/`PATCH`; o inyección en el parámetro `{id}` si se concatena en consultas o rutas internas. | **Alto** | Validar tipos y rangos en el servidor (nunca confiar en precios o descuentos enviados desde el cliente), usar consultas parametrizadas/ORM y validar estrictamente el formato de `{id}` (ej. entero positivo o UUID). |
| **Elevación de privilegios** | Un usuario autenticado con rol básico logra ejecutar `DELETE` o `PUT` sobre `/api/v1/products/{1}` por falta de verificación de permisos en el *handler*. | **Crítico** | Verificar autorización en cada operación sensible en el servidor (nunca solo en el *frontend*) y aplicar el principio de mínimo privilegio. |

---

## 3. Riesgos clave específicos de APIs REST (OWASP API Security)

* **Si el producto pertenece a un vendedor o tienda específica, comprobar que el usuario autenticado tenga propiedad o permiso sobre ese recurso antes de leerlo, editarlo o borrarlo.**
* **Si `{1}` es un entero secuencial (`1, 2, 3...`), es fácil enumerar todo el catálogo; considera usar UUIDs/ULIDs si no quieres exponer el volumen o secuencia de registros.**

---

## 4. Lista rápida de verificación antes de desplegar

1. **Validación de `{id}`:** Rechazar valores inválidos con `400 Bad Request` o `404 Not Found` antes de consultar la base de datos.
2. **Autorización en cada método:** Confirmar qué roles pueden hacer `GET`, `PUT`, `PATCH` y `DELETE`.
3. **Logs y monitoreo:** Alertar ante picos de errores `401`/`403`/`429`/`500` o cambios masivos en productos.
